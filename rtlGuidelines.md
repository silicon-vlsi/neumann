# Verilog / SystemVerilog Coding Guidelines (Wally Style)

> Source: Harris, Stine et al., *RISC-V SoC Design*, Ch. 4 §4.3–4.5 ("Wally Style Guidelines").
> Numbers like **[G4.12]** refer to the book's guideline numbers.
> Scope: **synthesizable RTL only**. Testbenches may look like software and are exempt.
> Consistency matters more than any single rule, but deviate only when there is a real need, and say why in a comment.

**Instructions for Claude / code generators:** follow every rule below when writing RTL. If a rule conflicts with the user's explicit request, follow the user and add a one-line comment at the deviation.

---

## 1. Quick Reference (the 20 rules that matter most)

1. Language: SystemVerilog. Use `logic` for every signal except tristate nets. [G4.8]
2. Declare **every** internal signal, including 1-bit ones. No implicit nets. [G4.6]
3. `clk` and `reset` are lowercase. All other signals are `UpperCamelCase`. Constants/parameters are `MACRO_CASE`. [G4.1–4.3]
4. Pipeline-stage signals get a stage suffix (`F D E M W` by default). [G4.4]
5. Use a source-unit prefix when similar signals come from different blocks (`IEUResultM`, `MDUResultW`). [G4.5]
6. Buses are little-endian: `[31:0]`, never `[0:31]`. [G4.9]
7. Fully synchronous design: one clock `clk`, posedge-triggered flops only. No latches, no negedge flops, no async logic unless essential and documented. [G4.26]
8. Instantiate flops/memories through **modules**, not inline `always_ff`. [G4.27]
9. No `#` delays in RTL. [G4.28]
10. One module per file, file name = module name. [G4.29]
11. Control logic is **behavioral**; datapath is **structural**. [G4.33, G4.34]
12. Keep modules small; use hierarchy. [G4.35]
13. No `function`/`task` in synthesizable code. [G4.36]
14. Ports: by **order** for simple generic modules (flop, mux); by **name** (`.sig`) for everything else. Avoid `.*` outside top-level/wrappers. [G4.11–4.14]
15. Parameters via `#(parameter ...)`. Interfaces stay identical whether a feature is on or off. [G4.39, G4.40]
16. Use `if`/`for` generate without `generate/endgenerate`; name any generate block that declares things. [G4.41, G4.42]
17. `inout` only at the chip top level, declared `inout tri`. Internally use unidirectional buses plus muxes. [G4.7]
18. Indent 2 spaces, no tabs, lines ≤ 95 chars. [G4.16, G4.17, G4.23]
19. File banner comment on every file. [G4.43]
20. Comments explain intent/principle, not what the code literally does. [G4.44]

## 2. Signals

### 2.1 Naming and capitalization

| Kind | Convention | Example |
|---|---|---|
| `clk`, `reset` | flatcase | `clk`, `reset` |
| Signals, ports | UpperCamelCase | `RegWrite`, `ALUResultE` |
| Constants, parameters, macros | MACRO_CASE | `XLEN`, `PMP_ENTRIES` |

- Verilog is case sensitive. Pick one capitalization per signal and use it identically everywhere (`RegWrite` ≠ `regwrite`). Inconsistent case causes silent non-connections and breaks Tcl-based EDA scripts.
- Do not use snake_case for signals.
- CSR-style register names in the book use upper-case with underscores (`SATP_REGW`, `STATUS_MPP`); this is a reasonable exception for architectural register fields.

### 2.2 Pipeline suffixes and prefixes

- Suffix every pipeline-related signal with its stage: `F`=Fetch, `D`=Decode, `E`=Execute, `M`=Memory, `W`=Writeback.
  - Examples: `PCF`, `InstrD`, `ALUResultE`, `ReadDataM`, `ResultW`, `StallD`, `FlushE`.
  - Use longer suffixes (`FET`, `DEC`, `EXE`, `MEM`, `WRB`) only if there are many stages and single letters become ambiguous.
- Signals outside the pipeline (bus interface, page-table walker) have no suffix.
- A pipeline register takes stage *N* signals in and produces stage *N+1* signals out; combinational logic stays within one stage.
- **Components that span stages** (register file, bus interface, hazard unit) are bug-prone, so name carefully:
  - A signal generated inside the pipeline keeps the suffix of the stage that produced it.
  - A signal generated by such a component (e.g. the hazard unit) takes the suffix of the stage where it is **used** (`StallF`, `FlushD`).
- Prefix with the source unit (ALL CAPS abbreviation) when similar signals come from different units: `IEUResultE`, `MDUResultW`, `SCResultW`. Typical units: `IEU, IFU, LSU, FPU, SC, MDU`.

### 2.3 Declarations

- Declare all internal signals explicitly, even 1-bit ones.
- Everything is `logic`, except tristate nets.
- Bidirectional pins (`inout`):
  - Only in the top-level chip module, only when a real I/O standard needs it (e.g. GPIO).
  - Declare as `inout tri`.
  - Internally never use tristate buses; use unidirectional buses and multiplexers.
- Buses are little-endian: `logic [31:0] Instr;`
- Avoid passing arrays through ports (arrays, usually memories, stay inside a module). If unavoidable, declare the port as `input var logic [7:0] Name [N-1:0]`.
- Align declarations in a block (type, width, names in columns).

### 2.4 Port connections

| Situation | Style |
|---|---|
| Simple generic modules (flop, mux, adder) | Positional (by order) |
| All other modules | Named: `.Sig` (same name) or `.Sig(Other)` (rename) |
| Non-generic module instantiated once | Use the **same name** for port and connected signal, so `.Sig` shorthand works |
| `.*` wildcard | Avoid; allowed only in top-level or wrapper modules where nearly all names match |

- Keep a signal's name the same across the module hierarchy wherever possible. It makes tracing easy. Rename with `.Port(Signal)` only when entering a generic module.
- Pack several port connections per line in instantiations (within the 95-char limit).

```systemverilog
// Generic: by order
mux2 #(XLEN) ResultMux(ALUResultE, AltResultE, ALUResultSrcE, IEUResultE);

// Non-generic: by name, packed, same names where possible
mmu #(.TLB_ENTRIES(DTLB_ENTRIES), .IMMU(0)) dmmu(
  .clk, .reset, .SATP_REGW, .STATUS_MXR, .STATUS_SUM,
  .PrivilegeModeW, .DisableTranslation(SelHPTW),
  .PAdr(PreLSUPAdrM), .VAdr(IEUAdrM));
```

## 3. Formatting

- **Indent:** 2 spaces per nesting level; **never tabs**.
- **Line length:** max **95** characters (80 is also fine).
- Spaces around operators and after `if`, `case`, `for` keywords.
- **No** space before `;` `,` `)`, after `(` in module instantiations, or inside bus ranges (`[31:0]`, not `[ 31 : 0 ]`).
- `begin`/`end` only when a block has more than one statement; put `begin` on the same line as its `if/else/for/always` when feasible.
- Blank lines sparingly: after the internal-signal declarations, between modules, and between unrelated code sections.
- Banner comments (e.g. `// ---- Hazard logic ----`) sparingly, only in complex modules where hierarchy isn't a better split.
- Dense is preferred over sparse: it lets a reader see more code at once.

## 4. Synchronous Design and Sequential Logic

- Only three building blocks: **posedge flip-flops, standard memories, combinational logic**.
- Single clock named `clk` within a clock domain. Reset named `reset`.
- Forbidden unless essential and documented/reviewed: latches, negedge flops, asynchronous elements, derived/gated clocks written ad hoc. Interfaces to asynchronous peripherals are the main legitimate exception; comment them clearly.
- Clock-domain crossing is out of scope of these guidelines; if used, isolate it in its own documented module.
- **Instantiate flops and memories as modules** (e.g. `flop`, `flopr`, `flopenr`, RAM/ROM/regfile modules) rather than writing `always_ff` all over the design. Benefits: easy count of state bits, easy swap of sync/async reset, scan, or low-power cells.
  - Exception: FSM state registers using an `enum` type may use `always_ff` inside the FSM, since the enum type doesn't fit a generic `logic` flop module.
- **No `#` delays** in synthesizable code (testbench only).
- Idioms:
  - Combinational: `assign`, or `always_comb` with `case` / `if-else`. Assign every output on every path (no inferred latches); give `case` a `default`.
  - Sequential: `always_ff @(posedge clk)`.
  - FSM: state flops + `always_comb` next-state/output logic (next-state may be merged into the `always_ff` for brevity).
  - Use nonblocking `<=` in `always_ff`, blocking `=` in `always_comb`.

## 5. Modules

### 5.1 Organization
- One module per file; file name = module name (`alu.sv` holds `module alu`). Closely related tiny modules (e.g. generic muxes) may share a file.
- Keep modules small and readable via hierarchy, but don't over-fragment to the point where tracing signals and writing port lists wastes effort.

### 5.2 Declaration layout
- Module name directly followed by `(` with no space.
- **Non-parameterized:** ports begin on the same line as the module name.
- **Parameterized:** put `#(parameter ...)` and the opening `(` on the module line; ports on following lines indented 2 spaces; closing `);` on the same line as the last port.
- One `input`/`output` keyword per line. Ports of the same direction **and** width share a line. Align direction, width, and names in columns.

```systemverilog
module alu #(parameter WIDTH = 32) (
  input  logic [WIDTH-1:0] A, B,
  input  logic [2:0]       ALUControl,
  output logic [WIDTH-1:0] Result,
  output logic             Zero);
  ...
endmodule
```

### 5.3 Coding style by block type
| Block type | Style |
|---|---|
| Leaf cells, generic blocks, control logic | **Behavioral** (`assign`, `always_comb`, `case`, `if`) |
| Datapath | **Structural**: wire up muxes, flops, adders, ALU as submodules. Keep nontrivial control in a separate module. `assign` is fine for bit swizzling/concatenation. |

- Don't use constructs that hide the hardware being inferred. In particular avoid `function` and `task` in synthesizable code (testbench only).
- Write code whose hardware you can visualize first (comb vs. sequential), then pick the idiom that implies it.

## 6. Configurable Hardware

- Build generic, reusable, parameterized modules (mux, flop, adder, MMU, cache pieces).
- Use `#(parameter ...)` for per-module parameters (widths, entry counts).
- For the whole design, collect configuration in a parameter **struct** passed to the top module and submodules; the top reads values from a `config.vh` file. One config file per core/SoC variant.
- **Interfaces must not change with configuration.** When a feature is disabled, keep the port and tie unused outputs to 0 inside a conditional generate. Avoid `` `ifdef `` to remove signals, because it makes simulation/testbench code fragile.
- Generate rules:
  - Omit the optional `generate`/`endgenerate` keywords (plain `if (...) begin: name ... end` and `for (...) begin: name ... end` at module scope). *(The book notes this is controversial; follow the project's preference if it differs.)*
  - If a generate block declares signals or instances, **name it** with a label right after `begin` (`begin: mul`) so hierarchical names are stable for debug.
- Add assertion/legality checks (in the testbench) for configuration parameters: legal value sets (e.g. entries ∈ {0,16,64}), feature dependencies (e.g. D requires F), and legal cache geometry.

```systemverilog
if (FEATURE_EN) begin: feat
  logic [WIDTH-1:0] Tmp;
  ...
  assign Out = Tmp;
end else begin: nofeat
  assign Out = '0;            // interface unchanged; unused output tied low
end
```

## 7. Comments

- Every file starts with a banner: **file name, author name + email, date, purpose, license** (this also records authorship/copyright).
- Add a short comment at the top of each module explaining its principle of operation.
- Comment the *why* / big picture, not the literal action. Choose good signal names so line-by-line comments aren't needed.
- Document every exception to these guidelines (async interface, negedge use, `.*`, etc.) where it occurs.

```systemverilog
// Bad:   assign Ab = ~A;  // flip the bits
//        assign MinusA = Ab + 1;  // add one
// Good:
assign MinusA = ~A + 1; // two's complement negation of A
```

## 8. Pre-Commit Checklist for Generated RTL

- [ ] Header banner present (file, author, date, purpose, license)
- [ ] File name equals module name; one module per file
- [ ] `clk`/`reset` lowercase; signals UpperCamelCase; parameters MACRO_CASE
- [ ] Pipeline suffixes (F/D/E/M/W) and source-unit prefixes applied consistently
- [ ] All internal signals declared (incl. 1-bit), all `logic`, all buses `[N-1:0]`
- [ ] No latches (all branches assign; `case` has `default`), no negedge, no `#`, no tristate internally
- [ ] Flops and memories instantiated via modules (FSM enum state excepted)
- [ ] Datapath structural, control behavioral; no `function`/`task`
- [ ] Positional ports only for simple generic cells; otherwise `.Sig` / `.Sig(Other)`; no stray `.*`
- [ ] Interfaces identical across configurations; unused outputs tied to 0; no `` `ifdef `` for ports
- [ ] Generate blocks labeled when they hold declarations
- [ ] 2-space indent, no tabs, ≤ 95 columns, aligned declarations, minimal blank lines
- [ ] Comments explain intent; exceptions documented
